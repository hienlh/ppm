# `src/services/speech-to-text/`

## Map

- `src/services/speech-to-text/` — speech to text for the chat mic, run on the host. `whisper-catalog.ts` pins the whisper.cpp build and every model by SHA-256, `whisper-download.ts` streams and hashes in one pass onto a `.part` file, `whisper-install.service.ts` installs under `<ppm dir>/whisper` and proves the binary runs before calling it installed, `whisper-transcribe.service.ts` is one `whisper-cli` run per request (serialised — two at once just make both slow), with `whisper-hallucinations.ts` dropping the sentences the model invents as a second line of defence behind the VAD. Routes `src/server/routes/speech.ts`, browser side `src/web/hooks/use-whisper-voice-input.ts` + `src/web/lib/voice-wav.ts`, Settings pane `src/web/components/settings/voice-settings-section.tsx` (the engine choice only appears once it is installed), e2e `bun tests/e2e/whisper-e2e.ts`

## Gotchas

- **Whisper invents speech out of silence, and in Vietnamese it invents the same YouTube outro every time**: six seconds of digital silence transcribes as "Hãy subscribe cho kênh Ghiền Mì Gõ Để không bỏ lỡ những video hấp dẫn" on both `small` and `large-v3-turbo`, and pink noise as "Cảm ơn các bạn đã theo dõi và hẹn gặp lại." — so the Silero VAD model (885 KB) is downloaded beside every speech model and `--vad` is not a tuning knob: with it both come back empty, and in 0.3s rather than seconds. Four more traps in the same install. The browser's own recording is **not** a format whisper.cpp can read — Chrome records Opus in WebM, Firefox Opus in Ogg, Safari AAC in MP4, while whisper reads wav/flac/mp3/Vorbis-ogg — so the conversion is done in the browser (`recordingToWav`, an `OfflineAudioContext` at 16 kHz, which is also what makes the upload 32 KB/s), because doing it on the host would mean requiring ffmpeg there as well. The published Linux build needs **glibc 2.34** and GCC 11's libstdc++, so on an older host (Ubuntu 20.04 is 2.31) every file downloads fine and only the first sentence fails — the installer runs `whisper-cli --help` once so that surfaces as an install error naming the cause. macOS has **no** CLI in the release at all (its asset is an xcframework, a library for Swift apps), so a Mac installs Homebrew's `whisper.cpp` and PPM looks for `whisper-cli` at `/opt/homebrew/bin` and `/usr/local/bin` as well as on PATH — a launchd-started PPM has neither prefix in its PATH. And whisper.cpp defaults to **4 threads**, which is worth raising and worth capping: on a 24-thread i9-12900K a 10s clip took 12.0s at 4 threads, 8.1s at 8, 5.6s at 16 and 5.4s at 24. The VAD is not quite the end of it either: it stops every non-speech clip measured here (silence, white noise at four levels, 50 Hz hum, a 440 Hz tone, brown noise, typing, a cough, a breath, room tone — each of which *without* it comes back as that same one sentence, byte for byte), but a live install still produced it, so `whisper-hallucinations.ts` drops the invented sentence by whole segment — `-nt` prints one line per segment, which is what makes dropping one safe when real speech sits either side. The two knobs that look like the fix are not: `--suppress-nst` changes nothing at all, and `-nth 0.3` empties the invented sentence **and** a perfectly clear 10s dictation with it.
