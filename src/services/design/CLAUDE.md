# `src/services/design/`

## Map

- `src/services/design/` — Design mode: a design is `designs/<slug>/` with its canvas data in the git-ignored, unwatched `.design/`. `design-store.service.ts` (folders, `design.json`), `design-snapshots.service.ts` + `design-restore.service.ts`/`design-restore-journal.ts` (history, crash-safe restore), `design-turn-snapshot.ts` (a snapshot after each design turn, scheduled from `chatService.sendMessage`), `design-instructions.ts` + `design-tool-policy.ts` (the per-turn instructions `chatService.prepareSendOptions` adds, and the `acceptEdits` policy), `design-skill-install.service.ts` (Settings → Design's Install for the suggested skill: the pinned npm tarball laid out exactly as upstream's `uipro init --global`, checked by `tests/e2e/design-skill-install-e2e.ts`), `preview/` (capability tokens, CSP, parse5 `data-ppm-id` instrumentation, print view), `bridge/` (the in-frame script, shipped as source), `source/` (the patchers behind tweaks and move/resize), `comments/`, `export/` and `design-edit-undo-journal.ts`. Routes `src/server/routes/designs.ts` with its `design-*.ts` sub-routers, and `design-preview.ts` for the canvas; protocol `src/shared/design-bridge-protocol.ts`; UI `src/web/components/design/` with client helpers in `src/web/lib/design/`; docs `docs/architecture/workspace-and-ui.md` → Design mode; e2e `tests/e2e/design-mode-e2e.mjs` (fixture server and scripted provider in `tests/e2e/fixtures/design-mode-server.ts` / `design-script-provider.ts`)
- `src/services/design/share/` — design share links (docs `docs/architecture/workspace-and-ui.md` → Design mode → Share links): `design-share-code.ts` (derived codes), `design-share-links.service.ts` + `design-share-links-store.ts` + `design-share-resolve.ts` (links, pinned snapshots, status), `design-share-comments.service.ts` (a reviewer's view of the threads, 304 ETags), `design-share-rate-limit.ts` + `design-share-client-key.ts`, `design-share-address.ts`, `design-share-notifier.ts` (`design_review`); allow-list `preview/design-guest-alias.ts`, guest bridge `bridge/guest-bridge.ts`, replies in `design-comment-replies.service.ts`. Owner routes `src/server/routes/design-shares.ts` (`/api/project/:name/designs/:slug/shares`) and `design-share-address.ts` (`/api/design-shares/address`); reviewer routes `src/server/routes/design-share-guest*.ts` on `/s/<code>`; owner UI `src/web/components/design/share/`; reviewer page `src/web/design-share-page/`, built by `vite.share.config.ts` inside `build:web`. e2e `PPM_PLAYWRIGHT_MODULE=<playwright>/index.mjs node tests/e2e/design-share-e2e.mjs` and `tests/e2e/design-comment-threads-e2e.mjs`; Markdown/Mermaid/docx sanitising `tests/e2e/markdown-sanitize-e2e.mjs`

## Gotchas

- **A design canvas trusts a message for its nonce, not its source, and the frame only ever proposes writes**: a `sandbox="allow-scripts"` frame can still navigate itself, and the page it lands on *is* the iframe's `contentWindow`, so an `event.source` check alone accepts a foreign page. The parent also requires the per-load nonce (`?n=`), the bridge blocks link clicks and `navigate` in the frame, and `connect-src` own-source plus the 3 s liveness reload are the boundary (`'unsafe-eval'` adds nothing `'unsafe-inline'` does not). A shell `frame-src` would hard-block self-navigation but also stop html-preview frames following external links; that decision is still open, so no shell header is sent. A `transform-commit` is written only if `design-transform-proposal.ts` finds Move on, the parent's own target, the `ready` gen and `navigator.userActivation.isActive`, and the server then re-checks gen and tag and rate-limits. The same parent-window rule is why a design never goes into picture-in-picture (`NON_PIP_TAB_TYPES`): in PiP the iframe's parent would be the PiP window. A floating window keeps the iframe in the main document, which is why a design may (and on a desktop by default does) open in one.
- **A design canvas reloads by getting a new `src`, and every `ready` is a new document**: the frame's origin is opaque, so `location.reload()` is not the parent's to call; `use-design-canvas.ts` sets a new URL with a new nonce. The tab pool reparenting the iframe (a split, a moved tab) reloads it too, with the *same* `src` and nonce, so frame-side state must be restored from `bridge.onReplay` on every `ready`, not once. `data-ppm-id` is the start-tag offset in one version of the file: valid only with the `gen` it came with, and a comment whose text cannot be found again is Detached rather than guessed.
- **`.design/` is invisible to the watcher and to git on purpose**: history and comments live in `designs/<slug>/.design/`, which `file-watcher/ignore-rules.ts` skips and whose own `.gitignore` is `*`, so anything waiting for a `file:changed` there waits forever. They refresh on `design:history_changed` / `design:comments_changed` from `/ws/global`. A user's own unrelated `.design` folder gets no live tree refresh either.
- **Bridge features cannot close over anything**: `bridge-script.ts` ships each feature as `fn.toString()`, so an import, a module constant or a helper called by name compiles, passes review, and is `undefined` in the frame. Everything arrives through `ppm`, shared helpers as `ppm.lib`. Loading the module throws if the script contains `</script`, `<script` or `<!--`, and `bun build` of `bridge-script.ts` followed by `new Function(BRIDGE_JS)` checks that the shipped bundler kept it intact.
- **Design exports are octet-stream Blobs, and the view tabs are real links**: a `blob:` URL has PPM's origin, and a browser that ignores `download` (iOS Safari) would open an HTML one and run the design beside the token in `localStorage`. Print and "Open in new tab" are `<a target=_blank rel="noopener noreferrer">` to tokens minted when the menu opens, because a `noopener` `window.open` cannot report a blocked popup. `allow-modals` is reachable only through a print-purpose token; the CDN hosts the design CSP allows (jsdelivr, unpkg) run any npm or GitHub code, which is accepted.
- **A reviewer's files never go through the canvas's `systems/<id>/**` alias**: for the `default` app that alias is `designs/` itself, i.e. every other design and the live copy of the shared one. A share link serves its pinned snapshot plus `design-guest-alias.ts`'s allow-list (`tokens.css`, and the snapshot's own app's `tokens.css` + `kit/**`, live), with the kit contained in its own folder so a `kit` that links elsewhere under `designs/` is refused.
- **Share codes are derived, never stored**: HMAC of link id + code version under `<ppm dir>/design-share.key`, with only the code's hash in the database, so a copied `ppm.db` or backup opens no link and the owner can still copy one again. `resolveShareCode` also re-derives the code and compares in constant time, so a link waiting for a new code does not open for its old one. Deleting the key retires every code without a restart.
- **Behind the supervisor every LAN and Tailscale reviewer is one loopback address**: the share routes' client key is `"local"` for all of them (`CF-Connecting-IP` is believed only from loopback with the tunnel's `Host`), so write spacing is keyed by client *and* reviewer key, or a reply sent right after a colleague's comment is refused; the per-link cap bounds a sender that invents keys.
- **The design CSP names its own files with a scheme, under both `https://` and `http://`, never scheme-less**: a scheme-less source takes its scheme from the document's origin, and in a `sandbox="allow-scripts"` frame WebKit reads that off the opaque origin, so it matches nothing. WebKit 26.4 and 26.5 refused every stylesheet, image and script of the page (the canvas check listed each as `csp: … blocked`); 26.6 fixed that in the web process, but the network process still checks `connect-src` against a policy it builds from the origin `null` (`NetworkLoadChecker::contentSecurityPolicy`), so the page's own `fetch` stayed refused. Both schemes go out because behind a tunnel the browser's scheme is not the one PPM sees. Chromium and Firefox take the scheme from the URL, which is why nothing desktop-only caught it; `tests/e2e/design-csp-engines-e2e.mjs` runs the policy in WebKit.
- **A leading BOM makes parse5 drop the locations of `<html>`, `<head>` and `<body>`**: it is read as body text, so those explicit start tags lose `sourceCodeLocation`. Strip it first and address everything in the BOM-less text (`decodeDesignText`); parse5 offsets are UTF-16 code units of exactly the string parsed, as `String#slice` counts them, and `startTag.attrs` is keyed by the lowercased source name.
