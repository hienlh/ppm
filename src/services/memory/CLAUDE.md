# `src/services/memory/`

## Map

PPM's own memory store, shared by Claude, Codex and Antigravity. Every memory is one Markdown file with flat frontmatter; `index.db` beside them (FTS5 + vectors) can always be rebuilt from the files. Each provider's native memory is copied in **one way** before a chat message; chats get a short list in the shared context and four tools on `ppm-tabs`. Spec: `specs/ppm-shared-memory/`.

- `memory-types.ts`, `memory-paths.ts` (`<ppm>/memory/projects/<sha256(projectKey)[0:16]>/`, `<ppm>/memory/global/`, `index.db`, `<ppm>/memory-embed/`), `memory-file.ts` (parse/serialize, `revision` = sha256 of the file, 12 hex).
- `memory-redact.ts` — credential values → `[REDACTED]`; prose words like "token" stay.
- `memory-store.ts` — the one write path: redact, temp file + rename, one lock per folder, revision check, refuses a *tool* write or archive of a memory whose `source` is not `ppm`.
- `memory-index.ts` — `index.db` (opened `busy_timeout` first), `reconcile(dir, scope, key)` by mtime/size, `textSearch` (already quotes and ORs the words), vectors by model; a corrupt file is renamed `index.db.broken-*` and rebuilt.
- `import-claude.ts`, `import-codex.ts`, `import-antigravity.ts` — read-only importers returning `{ items, skipped, error? }`; never throw for a missing or locked source.
- `memory-sync.ts` — `memorySync.ensureSynced(projectPath)`: metadata-only fingerprint, single flight per project, create/overwrite on `origin_hash`, archive what vanished, status in `sync-status.json`; `syncAll()` for Sync now.
- `memory-search.ts` — FTS + brute-force cosine, fused `max(v,f) + 0.3·min(v,f)` (ranks only); each result labelled `match: strong | weak` from `MemoryIndex.coverage` (the query's words it holds, idf-weighted, ≥ 0.3) or its similarity's z-score in the store (≥ 4, with ≥ 20 vectors); strong first. `memory_search` lists only strong results, else says nothing matches clearly and shows 3. Text only (with a reason) when the embedder is off, failing or slower than 3 s.
- `memory-context.ts` — `buildMemoryList()`: the `<ppm_memory>` block, 6,000 chars, recipient's own source left out.
- `memory-settings.ts` — `memoryEnabled(ai)` (unset → follows the memory tools' switches; always off when `share_provider_context` is off), `currentEmbedder(ai)`, `publicMemorySettings(ai)` (never the key).
- `memory-host.ts` — the **memory host** (`ppm __memory__`, a mode of `src/index.ts`): every request below that reads a file, the index or an embedder runs there, never on the server's main thread. JSON lines over stdio (`{ready}`, `{id, op, args}` → `{id, ok, result|error}`, `{event}`); ops `configure`, `prepareChat`, `syncAll`, `syncStatus(File)`, `queueStatus`, `kick`, `indexList`, `tool`, `testLocal`. `inProcessMemoryChannel()` runs the same handler in a test's own process.
- `memory-host-client.ts` — the server's side: `memoryHost()` (lazy spawn, one per server), `memoryHostTools()` for `ppm-tabs`, `kickWhenInstalled`, `stopMemoryHost()` at shutdown. Sends `configure` (memory settings, Codex homes incl. accounts, project paths) before a request whenever that changed or the host is new.
- `memory-runtime.ts` — the host's wiring: the shared embedding queue on the settings `configure` sent, syncs and tool writes (`memoryWritten`) kicking it, and the listener the host forwards to the server.
- `embedding/` — `api-embedder.ts` (OpenAI-compatible `/embeddings`), `local-embedder.ts` (a `bun` child running `embed-host.mjs` from the install dir, JSON lines over stdio, exits after 10 idle minutes), `local-install.ts` (one-click install), `embed-queue.ts` (batches of 16, 60 s per batch, model change drops old vectors; last model kept in `embed-model.json`).
- Wiring: `chat.service.ts` `prepareSendOptions` (`memoryHost().prepareChat`: sync + list), `provider-shared-context.ts` (`ppmMemory` drops native memory indexes), `tab-tools-mcp/memory-tools.ts` (run by the host), `src/server/routes/memory.ts` (`/api/memory`, asks the host), UI `src/web/components/settings/memory-settings-section.tsx` + `memory-embedding-source.tsx`.

## Gotchas

- **One way only, never write into a provider's folder or database.** Basic Memory removed two-way sync because it deleted files. An imported memory is owned by its source: a tool write to it is refused, and a hand edit in PPM's copy is overwritten the next time the source changes.
- **A provider that reports an error keeps its copies.** Archiving "everything that was not returned" after a locked Codex database would archive every Codex memory.
- **`remove_diacritics` does not fold `đ`.** It is its own letter, not `d` plus a mark, so `fold()` maps it before indexing and before every query.
- **No `sqlite-vec`.** A native SQLite extension does not load into macOS's system SQLite or into the compiled binary; brute-force cosine over a few thousand 384-dim vectors is under 10 ms.
- **The local model cannot be compiled into `ppm`.** `@huggingface/transformers` loads `sharp` on import and `bun build --compile` dies with `Could not load the "sharp" module` (measured). It lives in `<ppm>/memory-embed/` with its **own `package.json`** (or `bun add` installs into a parent) and runs as `[resolveBunPath(), embed-host.mjs]`. It costs ~650 MB on disk and ~1 GB of RAM while loaded, hence the idle exit.
- **e5 scores sit in a 0.75–0.85 band, and the top text hit is always 1.0.** Neither the cosine nor the fused score can say whether a result answers the query ("zebra teapot" scored 1.24 against 1.23 for a real hit). Never filter on a fixed similarity; the `match` label uses relative signals, calibrated on 109 real memories: every answered query's best result held ≥ 0.33 coverage, every unanswerable one ≤ 0.07; meaning alone stood at z 4–6 for answers, ≤ 3.44 for nonsense. Re-measure before moving `STRONG_COVERAGE` or `STRONG_Z`.
- **Never let memory stop a message.** A failing sync or index read is logged and the message goes out with whatever list there is; a host that does not answer sends it with none.
- **Nothing the host imports may reach the database or config**, and the client may not import the memory work itself (no fallback on the main thread). `memory-host-imports.test.ts` walks both graphs. That is why `projectKey` lives in `src/services/project-key.ts`, the sync takes its Codex homes and projects from `setMemorySyncSources`, and `EMBEDDING_OFF_REASON` sits in `embedder.ts`.
- **The host's stdout is the protocol.** `main()` installs the file log sink with `routeConsole`, so a stray `console.log` goes to `ppm.log`; the client still skips (and logs) any line that is not JSON.
- **The host must never keep its parent alive** (a `ppm chat` CLI would not exit). Measured on Bun 1.3: a pending read of a `Bun.spawn` stdout keeps the process alive even with the child unref'd, and `ref()` after `unref()` cannot be undone. So the client spawns through `node:child_process`, unrefs the child and its stdout once, and relies on each request's deadline timer to keep the loop up while it waits. `memory-host-client.test.ts` runs a real CLI-like script and asserts it exits.
