# `src/services/tab-tools-mcp/`

## Map

- `src/services/tab-tools-mcp/` — the AI's tab tools, `open_file` (optional `line`), `open_preview`, `open_url`, `read_terminal` and `run_in_terminal`, given to every chat that is not a design session while any is on in Settings → Tools (`ai.ppm_tools`, decided by `src/shared/ppm-tools.ts`; `open_file`/`open_preview` never switched there follow the older single switch `ai.tab_tools`, the other three default on, so the server reaches every chat by default); Claude's claude.ai Artifact tools are turned off while `open_preview` is on (`CLAUDE_CODE_DISABLE_ARTIFACT=1`), and a call to a tool turned off since is refused at the endpoint (`unavailable` in `mcp-http-endpoint.ts`), because a chat keeps the tools it started with. `/api/tab-tools-mcp` (`tab-tools-mcp-endpoint.ts`, mounted before auth) is built from the same parts as `/api/design-mcp`: `src/services/mcp-http-endpoint.ts` (JSON-only Streamable HTTP, a request with an `Origin` refused, 64 KB cap) and `src/services/mcp-session-tokens.ts` (per-session capability tokens, memory only, looked up by SHA-256); `tab-tools-mcp-tokens.ts` binds a token to the session id alone, so a warm spare's token is the one its session's turns mint. `tab-target.ts` resolves the agent's `path` under the editor's own read rules, and `tab-open-broker.ts` sends `tab_open` over the chat WebSocket and waits for the first `tab_open_result` (8 s for a file, 40 s for a page; 4 calls in flight and 20 a minute per session) — `deliverTabOpen` in `src/server/ws/chat.ts` picks the device that sent the turn's message, else every device showing the chat, and never buffers it for replay. Protocol and the per-provider tool names in `src/shared/tab-open-protocol.ts`; provider wiring `tabToolsMcpServers` (`claude-agent-sdk-query-options.ts`) and `tabToolsMcpConfig`/`tabToolsMcpEnv` (`codex-thread-params.ts`), from the access `chatService.prepareSendOptions` mints. Browser: `src/web/lib/open-ai-tab.ts` (answers `tab_open` from `use-chat.ts`: opens the tab, waits for the page, runs its check), `ai-tab-placement.ts` (pure: beside the chat on a desktop, the whole screen on a phone), `html-preview-loads.ts` (which preview shows which page, by load), `tab-tool-call.ts` + `src/web/components/chat/tab-tool-card.tsx` (the card and its Open button). The three tools that take no file: `open-url-tool.ts` (host servers only; an existing forward, else a private Tailscale forward it starts, else the address itself, which `openAiUrlTab` accepts only on a page loaded from loopback), `terminal-tools.ts` (`read_terminal` over the chat's project terminals plus the ones it opened; `run_in_terminal` starts the shell, has the device dock it via `openAiTerminal`, types one checked line with no newline) and `terminal-text.ts` (the raw buffer replayed through `@xterm/headless` into the lines the screen shows); their card is `src/web/components/chat/device-tool-card.tsx`. The HTML preview route serves the design canvas's CSP (`buildDesignCsp`, so the design CDNs load) and injects `design/bridge/html-preview-bridge.ts`, the design bridge's core plus its self-check. Docs `docs/architecture/ai-chat-and-providers.md` → AI tab tools; e2e `PPM_PLAYWRIGHT_MODULE=<playwright>/index.mjs node tests/e2e/ai-tab-tools-e2e.mjs` (scripted provider in `tests/e2e/fixtures/tab-tools-server.ts`, which also mounts the terminal socket; `PPM_TAB_TOOLS_WEB_DIR` reuses a scratch build; a stand-in `tailscale` on its `PATH` keeps `open_url` off the real tailnet) and `tests/e2e/html-preview-cdn-check-e2e.mjs`

## Gotchas

- **Codex renames a new chat during its first turn, so anything holding a session id across a turn has to follow it**: the tab tools' token is minted under PPM's id and handed to the Codex app-server in its environment, for the life of that process. During the first turn Codex emits `session_migrated` and `ws/chat.ts` re-keys `activeSessions` and the sockets to the thread id — so every later `open_file`/`open_preview` named an id with no sockets, and in a new Codex chat the tools answered "no device" while the chat sat open in front of the user. `tab-open-broker.ts` keys its pending calls, limits and delivery by `resolveMigratedSession(id)`. Claude keeps its id, which is why only Codex showed it.
- **Stripping ANSI codes from a terminal buffer leaks what the screen never showed**: a line editor redraws in place, so zsh-autosuggestions draws the rest of a history entry in grey and the next key erases it with cursor moves — a regex that drops escape sequences keeps that text and hands the AI the user's shell history as if it were output. `read_terminal` replays the buffer into `@xterm/headless` at the terminal's own size instead (`terminal-text.ts`), which also keeps a progress bar's last state and a full-screen program's screen; any new reader of terminal output should go through it.
- **An AI uses PPM's tool only if it does not think it has a better one**: with the user's Playwright MCP available, Opus given `open_preview`'s first description wrote the page, checked it in its own headless browser for four minutes (28 Playwright calls) and opened the tab only at the end — the user watched nothing. Saying *when* to call (as soon as the file is written; the user watches while you fix) and that the check needs no browser of its own put the call 5 s after the Write (Codex's came 34 s after its Write). Opus still opened its own browser afterwards, but only for what the check does not cover: hover tooltips and dark mode. The first run also inherited a max effort, so the two changes are not separated. Claude Code 2.1.280+ defers MCP tools, so a session's first call to either tool costs a `ToolSearch` round first.
