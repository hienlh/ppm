# `src/services/port-forward/`

## Gotchas

- **A forwarded page that refuses framing is let into PPM's tab by the hop, never by stripping the header**: the web-preview tab is an iframe on PPM's origin, so Rails' default `X-Frame-Options: SAMEORIGIN`, Django's `DENY` or any CSP `frame-ancestors` rendered a blocked frame. Deleting those headers would let every site frame the dev app, which matters for a public Cloudflare forward. `frame-ancestors.ts` translates instead: SAMEORIGIN becomes `frame-ancestors 'self' <PPM>`, DENY becomes `frame-ancestors <PPM>`, and an existing `frame-ancestors` gains PPM's origins (`'none'` dropped, since it cannot stand beside a source). `X-Frame-Options` cannot name an origin (`ALLOW-FROM` is ignored everywhere), and an enforced `frame-ancestors` makes browsers skip it. PPM's origin has to come from the browser: the server cannot know every name it is reached by (LAN address, tunnel, reverse proxy). So the tab POSTs `location.origin` to `/api/tunnels/frame-ancestors` before its frame loads and again on Reload; the list is in memory like the hops, so a restart forgets it. CSP has no IPv6 literal, so a PPM opened at `http://[::1]:<port>` cannot be named. `bun tests/e2e/forward-hop-framing-e2e.ts` checks the verdict in Chromium, Firefox and WebKit: PPM may frame every page, another site still may not. In a UI e2e, note that Forward opens the tab by itself, so nothing read after Forward is a "before".
