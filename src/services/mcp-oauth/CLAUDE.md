# `src/services/mcp-oauth/`

## Map

- `src/services/mcp-oauth/` — MCP sign-in for `needs-auth` servers: `mcp-oauth-flows.ts` (one prompt-less Claude subprocess per flow, opened by the provider's `openMcpControlQuery`), `mcp-status-probe.ts` (cached per-directory status), `mcp-oauth-redirect.ts` (pure redirect/host rules). Routes `src/server/routes/mcp-auth.ts` (public `GET /api/mcp-auth/callback` mounted before auth), chat sync `src/server/ws/chat-mcp-sign-in-sync.ts`, UI `src/web/components/mcp-auth/` (dialog/bottom sheet, chat bar, the list shown in Settings → AI Provider and the AI Resources panel), e2e `tests/e2e/mcp-sign-in-e2e.mjs`

## Gotchas

- **MCP sign-in works in SDK mode, through methods `sdk.d.ts` does not declare**: a server the CLI reports as `needs-auth` (an HTTP server with OAuth such as Vanta, every plugin connector) used to be unusable from PPM because the CLI's `/mcp` screen does not exist without a terminal — and the model, reading the CLI's own "this session is non-interactive" hint, told users to go and open one. The `Query` object in fact carries `mcpAuthenticate(name, redirectUri?)` and `mcpSubmitOAuthCallbackUrl(name, url)` (in `sdk.mjs`, stripped from the typings), and a **prompt-less** streaming `query()` answers them — and `mcpServerStatus()` — in about a second with no model call. `src/services/mcp-oauth/` runs each sign-in in a subprocess of its own, and that process has to outlive the dialog's request: with the default `redirectScheme: "localhost"` the CLI's callback listener lives *inside* it, so closing it early strands the browser on a dead page. An https origin gets `redirectUri` pointed at PPM's public `GET /api/mcp-auth/callback` instead, which is what makes a phone over a tunnel work (Vanta accepts it); plain http falls back to the localhost listener plus a paste box. Four traps. The tokens land in the CLI's shared credential store, so a *running* chat still reports the server `needs-auth` until `reconnectMcpServer` is called in it — `chat-mcp-sign-in-sync.ts` does that, and drops an idle subprocess that still cannot see them. claude.ai connectors (`claude.ai <name>`, scope `claudeai`) answer "Server not found" to `mcp_authenticate` in SDK mode, so the UI sends them to claude.ai's connector settings rather than starting a flow that cannot succeed. The expiry timer only starts once there is a link, so `mcpAuthenticate` and the status probe's reads are wrapped in `withTimeout` — a CLI that never answers would otherwise hold its subprocess for as long as PPM runs, and every caller shares the probe. And in an e2e, Bun's `fetch` reuses a pooled socket the server has already closed after a long idle stretch, so a request silently never arrives: that read as a hung sign-in until the server log showed no `starting sign-in` line for it — `tests/e2e/mcp-sign-in-e2e.mjs` sends `Connection: close`. `tests/unit/services/mcp-oauth-flows.test.ts` greps `sdk.mjs` for the undeclared methods so an SDK upgrade that renames them fails a test rather than the button.
