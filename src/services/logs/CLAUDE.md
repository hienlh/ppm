# `src/services/logs/`

## Map

- `src/services/logs/` — the Logs window, which replaced Report Bug. `log-store.ts` reads every log as one list — `ppm.log` and its rotated copies, `cloudflared.log`, and the browser rows the session trace already keeps (`browser-logs.ts`) — indexed per file inode as typed columns (`log-file-index.ts`, `log-columns.ts`: ~450k records in ~13 MB where objects cost ~200 MB), with the text read back a page at a time. `log-live.ts` is the live tail: a one-second poll that runs only while some view is subscribed over `/ws/global` (`logs:subscribe`). `log-issues.ts` is the Issues tab — the last 24 hours of errors and warnings grouped by `src/shared/log-fingerprint.ts`, then sorted by cause by Claude Haiku through `log-ai.ts` (`completeOnce`, the person's own account, no tools), remembered per fingerprint in `<ppm dir>/logs-issues.json`; Auto runs at most every ten minutes and only while something reads the issues. `log-report-draft.ts` drafts a report from chosen lines, `log-environment.ts` is its Environment block, `github-issues.ts` asks GitHub for labels and look-alike open issues — never posts. What the Logs window's own AI is shown and what goes into a report go through `src/shared/log-redact.ts` first, which takes out secrets whatever the switches say (a process's own stderr reaches `ppm.log` unredacted); Add to chat puts lines in a chat as they are. Routes `src/server/routes/logs.ts` (authenticated, like the old bug report's `/api/logs/recent` in `src/server/index.ts`, which nothing in PPM reads any more), shapes `src/shared/logs-model.ts` + `logs-api.ts`. UI `src/web/components/logs/` — a window on desktop, the `logs` tab below `md`, both through `open-logs.ts` — with the pure halves in `src/web/lib/logs/` (`logs-view-model.ts`: folding repeats, ranges; `logs-report.ts`: the issue Markdown and its URL limit). The GitHub button is a real `<a target=_blank>`, so it cannot be popup-blocked, and a body too long for the URL is copied instead

## Gotchas

- **A log line's timestamp is a claim, not its place in the file**: the live `ppm.log.1` held a record stamped `2026-10-06T03:06:13Z` among `20:49Z` ones. The old build logged tool output verbatim (`tool_result: … output=`), that output quoted an example log line from the docs, and the reader took the quoted line for a record of its own. Merged by timestamp, it carried everything after it in the file seven hours forward. `formatLogLine` still writes a multi-line message as it is, so any text that quotes a log line can do it again. `log-columns.ts` therefore orders records by an `order` key: the longest run of in-step timestamps (patience sort), with each line off that run taking the time of the last in-step line before it. `merge()` and the time-range search compare that key, and `ppm.log.3` → `ppm.log` are one chain read in file order; only separate logs are interleaved by time. Related: Show in Logs reaches lines older than the first page with `reach=<id>`, one request capped at `MAX_REACH` (15,000 lines) that answers `reachMissed: "far" | "gone"` rather than leaving an empty selection.
