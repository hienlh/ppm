# `src/services/session-file-baselines/`

## Map

- `src/services/session-file-baselines/` — the session review (the changes bar above the composer and the block-by-block Review tab): `session-file-baselines.service.ts` keeps each file's state from before the session's first write (`<ppm dir>/session-baselines/<session id>/`, first capture wins, 5 MB cap, credential paths never copied, 30-day prune), `session-file-changes.service.ts` compares it with the disk (git HEAD only as a fallback inside the project), `reverse-unified-diff.ts` works a Codex patch's "before" out, `shell-change-tracker.ts` brackets each Claude shell command with `git status`, `session-review-marks.ts` keeps what the user marked reviewed (a snapshot per file under `<session dir>/reviewed/`, written only at the version the browser showed; a file changed after its mark is diffed against the mark). Blocks are cut by `src/shared/review-blocks.ts`, shared because the server cuts them again from the disk before acting on a key the browser sent; `session-review-blocks.ts` records the kept ones per base hash, and `session-review-actions.ts` keeps, reopens and reverts blocks or whole files on disk (`/file-changes/answer`, refused as `stale` unless the file is at the version drawn) and undoes any answer all-or-nothing from its journal (`/file-changes/undo`). `session-file-history.ts` logs each file's state just before and after every call that writes it (`<session dir>/history/`, as line deltas), `session-file-blame.ts` replays that log to name the calls behind each block, and `session-turn-revert.ts` puts a turn's calls back where their lines are still intact (`/file-changes/revert-turn`: a preview first, then `stale` unless every file is at the previewed version). Captured by the Claude PreToolUse file-write hook and the shell hooks around each `Bash` call (`buildToolHooks` in `claude-agent-sdk-query-options.ts`) and by `codex-file-baselines.ts`. Routes `src/server/routes/chat-file-changes.ts`, shapes `src/shared/session-file-changes.ts`; UI `src/web/components/chat/session-changes-bar.tsx` + `session-change-row.tsx`, and `src/web/components/session-review/` (`review-desktop.tsx`, `review-phone.tsx` below `md`, `review-code.tsx` for the blocks and their turn chips, `review-tokens.tsx` for shiki colours), the chat's per-answer pill and tray `src/web/components/chat/turn-change-{rollup,tray,sheet,review}.tsx` over `src/web/hooks/use-turn-review.ts` + `src/web/lib/turn-review.ts` (the list reaches them through `session-changes-context.tsx`), turns from `src/web/lib/session-turns.ts` through `src/web/stores/session-turns-store.ts` (published by the chat, read by `use-session-turns.ts` when no chat is open), Show in chat through `src/web/stores/chat-jump-store.ts`, state `src/web/hooks/use-session-review.ts` over the pure `src/web/lib/session-review-model.ts`, data `src/web/hooks/use-session-file-changes.ts` + `src/web/lib/session-file-changes{,-client}.ts`; docs `docs/architecture/ai-chat-and-providers.md` → Session changes and review; e2e `bun tests/e2e/session-changes-e2e.mjs`

## Gotchas

- **A session's "before" for a file is PPM's to keep, because no transcript holds it**: Claude Code records a tool's `toolUseResult.originalFile` only for small files (measured: kept at 9,836 B, gone from 13.6 KB up), an Edit's `old_string` is a fragment at an unknown offset, SDK checkpointing is off, and git HEAD also holds whatever was uncommitted before the session began. So the session review reads `session-baselines/` (see Architecture), filled at PreToolUse **in every permission mode**. That last part is new: before it, a bypass-mode session — the default — installed **no PreToolUse hook at all** (the permission hook is skipped there by design), so anything added to the permission hook does not run for most sessions. `buildToolHooks` therefore gives bypass mode a file-write hook of its own (`PreToolUse[0]` there), while every other mode runs it from the permission hook once that has allowed the write — a denied write records nothing; `permissionHook()` in `claude-agent-sdk.test.ts` finds that `.*` one. Verified against the real CLI in bypass mode: the hook fires for a sub-agent's Write too. A record is hard-linked into place so the **first capture wins**; never "fix" a missing record by writing one later in the session, which would record a state the session itself produced. Shell commands are the exception that proves it: `shell-change-tracker.ts` reads a file's bytes *before* the command runs and records them only if the command moved it, and a file git did not list is HEAD — read from the **pre-command** HEAD, because `git commit` in the same command moves it (the post-command HEAD would name the new content as the "before"). Outside bypass mode that snapshot is taken by the permission hook once it has allowed the command, not by a hook of its own, so it cannot be taken while the approval prompt is still open — an edit made during that wait would otherwise be put on the command (checked with the real CLI: a file edited during a 1.5 s approval wait was not recorded).
