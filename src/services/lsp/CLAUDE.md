# `src/services/lsp/`

## Map

- `src/services/lsp/` — language servers for the editor. `server-registry.ts` says which binary serves which language and how to find it (project `node_modules/.bin`, then PATH, then PPM's own directory), `lsp-protocol.ts` is the `Content-Length` framing, `lsp-session.ts` owns one child process, `lsp-manager.ts` decides how many exist and shares them by *server + root directory*. `lsp-install.ts` is the Install button's host half, one plan per server: `bun add` of the registry's packages into `<ppm dir>/lsp-servers` — never `-g` — `go install` with `GOBIN` pointed at that same directory, `gem install --install-dir <lsp dir>/ruby` for Solargraph (spawned with `GEM_PATH` pointing there — `installedServerEnv` — and not offered on Windows, whose `.bat` binstub is unverified), a release download for clangd and lua-language-server (`lsp-release-catalog.ts`, version + SHA-256 per platform; staged beside the target, unpacked, started once with `--version`, then swapped in whole), and for rust-analyzer alone `rustup component add` **in the project's directory**, keeping no copy because the component belongs to whichever toolchain that project selects. All of them behind `POST /api/project/:name/lsp/install`, which takes a server **id** and never a package name; a toolchain PPM cannot find means no button rather than one that fails; the browser side is `retryUnavailableLspDocuments()` in `lsp-client.ts`, which reopens the files that had no server so an install needs no reopened tab. The same pair exists machine-wide at `/api/lsp/{servers,install}` for `settings/language-servers-section.tsx` — Settings is open on no project, so nothing project-local is consulted there — and that pane reaches the client through a **dynamic** import, because the lazy-boundary test scans all of `src/web`. That pane's Remove (`POST /api/lsp/uninstall`, Settings only — the editor's dialog is only ever shown for a *missing* server) is gated on `origin` from `availability()`, which is where `resolveCommand` found the server: only `ppm` and `rustup` may be removed, because a copy on `PATH` is the user's, one in a project is the repository's and `bundled` is PPM's own dependency. One npm package can serve several rows (`vscode-langservers-extracted` is JSON + HTML + CSS), which `serversSharingInstall` names so the confirmation can say so before the removal takes all three. Bridge at `src/server/ws/lsp.ts` on `/ws/project/:name/lsp`, status at `/api/projects/:name/lsp/status`. Browser side in `src/web/lib/lsp/` (client, Monaco conversions, providers, shadow models, F12 navigation) driven by `src/web/hooks/use-lsp.ts`. All of it is behind the `lspEnabled` setting — off by default, per device, never on below the `md` breakpoint — and mounted by `src/web/components/editor/editor-language-service.tsx`, which `code-editor.tsx` may only reach through `lazy()`. Real-server check: `bun tests/e2e/lsp-e2e.ts`

## Gotchas

- **`Content-Length` in the LSP framing counts bytes, not characters**: one multi-byte character anywhere in a payload — a curly quote in a hover, a Vietnamese identifier, an emoji in a doc comment — makes a character-counting decoder cut the body short, fail to parse, then read the next message's header as body. The stream never recovers and it only happens for some files. Also bound the header search (`MAX_HEADER_BYTES`): a server writing a panic trace to stdout has no `\r\n\r\n` to find, so without a bound the decoder buffers forever and the session looks healthy while serving nothing.
- **`typescript-language-server` needs TypeScript 5.x**: the 7.x line is the native port and ships no `tsserver.js`, so the server exits at `initialize` with "provides no tsserver". It reads like a broken install rather than the wrong major version, so the registry's install hint pins `typescript@5`.
- **A gem installed into PPM's own folder cannot find itself, and a release zip needs a tool Bun does not have**: `gem install --install-dir <dir>` writes a binstub that asks RubyGems for its gem, and `<dir>` is on no gem path — measured, it exits with `Gem::GemNotFoundException` unless spawned with `GEM_PATH` naming `<dir>` (`installedServerEnv`, threaded `resolveCommand` → `LspSession.start`). Solargraph's dependencies (prism, rbs, jaro_winkler) compile C, so a host with no compiler fails with "Failed to build gem native extension" and a message that ends on a log path; `lsp-install.ts` says what is missing instead and deletes the half-install gem leaves "for inspection" (a first install only — a working one being updated keeps its folder). For downloads: `Bun.Archive` answers "Unrecognized archive format" for a zip and GNU tar cannot read one either, so a zip off Windows needs `unzip` or `bsdtar` on PATH (Windows' own `tar.exe` is bsdtar), and a host with neither has no button.
