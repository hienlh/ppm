# `src/services/tailscale/`

## Map

- `src/services/tailscale/` — Settings → Remote Access → Tailscale, PPM at `https://<name>.<tailnet>.ts.net` through the Tailscale Service `svc:<name>`. `tailscale-cli.ts` finds and runs the CLI (shared with `port-forward/tailscale-forward.ts`), `tailscale-state.ts` reads the setup from `status --json`, `debug prefs` and `serve status --json` and changes nothing, `tailscale-login.ts` is the in-app sign-in (`tailscale up --json`, its link and QR code), `tailscale-app-service.ts` is the switch (the `tailscale_service` config row) and the start-up re-apply. The step order is `currentSetupStep` in `src/shared/tailscale-setup.ts`, shared by the server's refusal messages and the pane's checklist. Routes `src/server/routes/tailscale.ts` (`/api/tailscale`), UI `src/web/components/settings/tailscale/`, fake CLI for tests `tests/fixtures/fake-tailscale.ts`

## Gotchas

- **A Tailscale Service is three admin steps the CLI cannot take, and its approval is not in the serve config**: `tailscale serve --service=svc:<name>` refuses an untagged node (`service hosts must be tagged nodes`), cannot define the service (the admin console's Services page does) and leaves the host waiting for an admin. Whether that approval happened is only in `status --json`: `Self.CapMap["service-host"]` maps each service this node may host to its VIPs (`[{ "svc:ppm": [...] }]`), and `CapMap["services/<name>"]` is present for a definition the node can see. `--service` forces `--bg`, so tailscaled keeps the handler across PPM restarts and reboots: PPM's switch is a desired state, re-applied by `ensureServiceOnStartup`, and a switch never touched counts an address already pointing at PPM as on (the address this dev host is reached at was set up by hand). A `svc:<name>` pointing anywhere else is never taken over without `replace` (409 `code: "conflict"`), which is also what keeps a dev instance off the live one's name. Two traps in `tailscale up`: on a node with any non-default pref it refuses with `requires mentioning all non-default flags` and prints the command that keeps them, which `tailscale-login.ts` retries once; and a stopped node must get a bare `up`, because any flag, `--json` included, takes it into that same refusal. `tailscale debug prefs` carries the node's private keys (`Config.PrivateNodeKey`, the network-lock key): `parsePrefs` keeps three fields, so never log or return the raw output. On Linux tailscaled takes changes from root and its `OperatorUser` only, which is why the pane's operator step (`sudo tailscale set --operator=<user>`) comes before sign-in. Never run `tailscale up`, `login`, `logout` or a `serve` change against this dev host from a test; `tests/fixtures/fake-tailscale.ts` answers every command the pane uses.
