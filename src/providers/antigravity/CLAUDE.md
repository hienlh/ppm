# `src/providers/antigravity/`

A chat runs on `agy acp` (Agent Client Protocol: JSON-RPC 2.0 over stdio), one process per open chat, like `codex app-server`. History and the session list are read from the transcript files on disk, never from agy. The language-server code in `antigravity-connection.ts` remains only for the model list and the quota panel, which work only while the Antigravity app is open.

## Gotchas

- **A prompt sent mid-turn is queued, and the earlier prompt is answered at once**: agy answers the running `session/prompt` with `end_turn` (and no usage) as soon as a second one arrives, while that first reply keeps streaming to the end before the second prompt runs. Emitting `done` on every answer ended the turn in the middle of a reply. `inFlight` counts the prompts sent and not yet answered, and only the last answer ends the turn.
- **`session/load` replays the whole chat before it answers**: every earlier message and tool call comes back as a `session/update`. `loading` drops them, or a reopened chat would print its history again as if it were the reply.
- **agy hands its whole environment to every command it runs**: `agyEnv` (`acp-launch.ts`) is an allowlist plus `PPM_AI_CHAT`, and it is the whole environment of every process PPM starts for Antigravity: the chat, the `/usage` read, the sign-in and the language server (PPM's environment carries tokens; `antigravity-spawn-env.test.ts` pins the last two). The Google sign-in sits in the keyring, so the session bus (`DBUS_SESSION_BUS_ADDRESS`, `XDG_RUNTIME_DIR`) is on the list. An extra account is run with `HOME=<its home>` and `WSL_DISTRO_NAME=ppm`, the same as its `agy acp --login`, which makes agy keep that token in `<home>/.gemini` instead of the keyring.
- **`--app-data-dir antigravity` puts a chat in the Antigravity app's own store**: the app lists it, but only after the app restarts, and always under its "CLI Project" (agy ignores `ANTIGRAVITY_PROJECT_ID` and refuses `--project`). An existing chat is continued in the store its files are in. The app's store is used only while its `conversation_summaries.db` has `user_version` 3, the layout agy 1.5.2 and the app shared on 2026-11-07. Running in the app's store also makes agy rewrite the app's `builtin/` skills with its own.
- **agy adds a `[Notice] All your subagents and background tasks have been stopped…` step every time a chat is opened in a new process**: a `SYSTEM_MESSAGE` from `sender=system` like the messages the old agentapi path sent for the user, told apart only by `priority=MESSAGE_PRIORITY_LOW` (the user's were HIGH). The history parser drops the LOW ones; without that, each reopen showed the notice as a message from the user.
- **agy takes a system prompt only in `session/new`, and keeps it with the chat for good**: `_meta.antigravity.systemPrompt.append` on `session/load` or `session/prompt` is ignored without an error, while the one given at creation still applies after a reload in a new process and after `/compact` (measured 2026-11-07; 90 KB arrived whole). agy writes no transcript step for it. So the provider's Additional Instructions reach only chats PPM creates from then on (Settings says so), and a new chat's shared context goes there rather than into its first message. A chat agy already has still gets the context in a message.
- **agy names its slash commands only to an open chat**: in an `available_commands_update` after `session/new`, and during the replay of `session/load` (which is why it is read before the `loading` guard). No request lists them without a chat. `antigravity-commands.ts` keeps the last list per project in the config row `antigravity_slash_commands`, and the picker shows that list, or else the latest one any project got. The disk scan stands in only until agy has run once. The list is agy's own discovery: its built-in commands (`/goal`, `/compact`, `/schedule`…), `.agents/skills` and `~/.gemini/config` skills, and the app store's skills when the chat lives there. It never includes `.claude/skills`.
- **`/compact` sends nothing at all**: no update for the 5-7 s it takes, then `end_turn` with usage. The provider emits `compacting`/`compact_done` itself, so the tab shows "Compacting messages…" instead of a silent turn. In the transcript it is a `USER_INPUT` followed by a `CHECKPOINT` step holding the summary. The history parser skips that step, so a reopened chat shows `/compact` with no reply.
- **Background work lives and dies with the chat's process**: agy's notice on every reopen says its subagents and background tasks were stopped. `/schedule`, `/teamwork` and `/boost` run inside that process, which PPM closes on Stop and when it releases an idle chat.
- **Usage**: `outputTokens` already includes `thoughtTokens`, and `inputTokens` excludes `cachedReadTokens` (measured: input + cached + output = total). A turn's usage covers every model call in it, so it is not a context size.
- **The permission mode is read once per process**: the chat socket sends none with a follow-up, so a chat opened in bypass mode keeps answering agy's permission requests itself until its process is released or stopped. The same holds for Codex.
- **Each open chat costs ~270-290 MB** (agy 1.5.2 RSS). The chat socket's warm-idle cap and cache-expiry release bound how many stay open.
