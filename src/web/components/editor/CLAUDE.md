# `src/web/components/editor/`

## Gotchas

- **A lazy chunk boundary is one static import away from not existing, and it is invisible**: `code-editor.tsx` reaches the language service only through `lazy(() => import("./editor-language-service"))`, which is what keeps the LSP client out of the editor's chunk and — the part that actually costs something — keeps the code that asks the host for a server unreachable until the setting is on. One `import { anything } from "@/hooks/use-lsp"` anywhere on that static path merges the chunk back in and nothing about the UI looks different, so `tests/unit/web/editor-lsp-lazy-boundary.test.ts` enumerates the offenders instead. Importing even a *constant* from the lazy module counts; `import type` does not. Related: `lspEnabled` and `mobileWordWrap` are written with `persistDevicePref` (localStorage only) rather than `persistUiPref`, because the server round-trip that makes prefs survive an origin change also means the last device to write wins everywhere — and a desktop must not start an 854 MB server process for a phone.
- **`@monaco-editor/react` 4.7 disposes a diff's models before the diff editor holding them**, and Monaco 0.55 reports it as an uncaught "TextModel got disposed before DiffEditorWidget model got reset" on every unmount — every closed diff tab, every file a review steps to. `DiffEditor` in `diff-viewer.tsx` is the library component's parent and detaches and disposes the models in its own cleanup, which React runs first because it runs a removed subtree's cleanups parent before child (every layout one before any passive one). The layout effect there is margin, not the fix: measured on React 19.2, a `useEffect` cleanup in the wrapper also runs before the library's passive one. `diff-viewer-dispose-order.test.ts` mounts the real viewer over the real library and goes red without the cleanup. Separately, that file's word-wrap sync forced `wordWrapOverride2` onto the original editor in **inline** mode too, where the original is a hidden 35px column: every line wrapped many rows tall and the inline view padded the visible side to match, so a phone showed one changed line between screens of hatching (`.diagonal-fill`). Monaco itself keeps that editor unwrapped when inline; only a side-by-side original wraps now.
- **`handleEditorMount` in `code-editor.tsx` is memoised on `[isSql]`, so it sees the props of the render that created it**: a tab can be asked for a line before its editor exists — `open_file` with `line` on an HTML page open in preview mounts Monaco only when it switches to code — and the stale closure revealed the first render's target, i.e. none. It reads `revealTargetRef` now; anything else that handler needs from props has to go through a ref too.
