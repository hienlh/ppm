# `tests/e2e/`

## Gotchas

- **Playwright's `evaluate` is a user gesture, and so is every poll**: `navigator.userActivation.isActive` turns true for about 5 s after a `frame.evaluate`, in the parent too, so a "no gesture" test that polls for its result re-arms the activation it is testing and the forged write goes through. `design-mode-e2e.mjs` posts the forgery from a page timer 7 s after the last evaluate and reads the outcome from console messages, which Playwright observes without touching either document.
- **In a Playwright-driven preview check, a page error naming `localStorage` or `serviceWorker` is Playwright's, not the page's**: `addInitScript` runs in every frame, the sandboxed previews included, where storage access throws `SecurityError`, and `serviceWorkers: "block"` injects a read of `navigator.serviceWorker` that an opaque-origin frame refuses too. The bridge reports both as the page's own errors, so the check lists problems the page does not have. Guard init scripts with `window.top !== window` and filter the service-worker one (`ai-tab-tools-e2e.mjs`).
- **Headless Chromium cannot subscribe to push, so a push e2e has to enter at the service worker**: `pushManager.subscribe` there fails with `Registration failed - permission denied`, so no test ever reaches a real FCM endpoint. The two halves are checked apart: the server's by encrypting a real push (`src/services/web-push/`) to a local HTTPS receiver, the worker's with CDP `ServiceWorker.deliverPushMessage` for `push` and a `NotificationEvent` dispatched inside the worker (`page.context().serviceWorkers()` → `evaluate`) for `notificationclick`. Chrome accepts only `userVisibleOnly: true` subscriptions, so `sw.ts` shows a notification for every push and never drops one. Like wake lock and WebCodecs, push needs a secure context, and on iOS a Home Screen install too; the Notifications pane says which one is missing instead of offering a switch that cannot work.
- **Playwright's headless shell ignores `--unsafely-treat-insecure-origin-as-secure`**: the default `headless: true` launches `chromium-headless-shell`, where a page on a mapped name (`--host-resolver-rules=MAP ppm-remote.test 127.0.0.1`) stays an insecure origin and loses every API a browser keeps for secure contexts. That is how PPM's chat send was found broken on plain HTTP: it called `crypto.randomUUID`, so a turn never started and the test read as hung. Full Chromium (`channel: "chromium"`, also headless) honours the flag; `ai-tab-tools-e2e.mjs` launches it only for its device-that-is-not-the-host step.
